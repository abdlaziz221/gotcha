# Journal des décisions

Une ligne par décision qui engage l'équipe : la date, le choix, la raison. On ne supprime pas une décision dépassée : on en ajoute une nouvelle qui la remplace.

| D2 | 2 nov. | **PostgreSQL avec asyncpg** (Apache 2.0), jamais psycopg (LGPL) | Règlement : licences à réciprocité interdites |
| D3 | 2 nov. | **Aucune bibliothèque qui dépend de certifi** (MPL) : ni requests, ni httpx, ni detect-secrets. Lecture HTTP avec urllib ; détection des secrets par règles maison | Même raison. Le SDK MCP 2.x passe par httpx2 et truststore, sans certifi |
| D4 | 2 nov. | **Deux stockages derrière les mêmes ports** : memory (fichiers) pour développer, postgres pour la production ; tests de contrat communs | Personne n'attend la base ; branchement en changeant une variable |
| D5 | 2 nov. | **Le contenu vit dans `content/` (Markdown et YAML, versionné dans Git)** et est chargé en base par `scripts/seed.py` | Un fichier par piège : on écrit à plusieurs sans conflit ; historique et relecture par PR |
| D6 | 2 nov. | **Fiches et pièges en JSONB** dans PostgreSQL, avec des colonnes extraites pour filtrer et chercher | Le modèle Pydantic se sérialise tel quel ; schéma simple à faire évoluer |

| D16 | 2 nov. | **CI sur CircleCI (plan gratuit)** tant que GitHub Actions est bloqué ; workflows GitHub Actions retirés (ils échouaient sans tourner et envoyaient des notifications ; récupérables dans l'historique git, commit 3fc9c27) ; Dependabot retiré | Le compte propriétaire est verrouillé « pour un problème de facturation » sans aucun usage ni paiement : seul le support GitHub peut le lever. | D17 | 2 nov. | **Recherche faite dans l'application, pas en SQL** : PostgresStore lit les fiches visibles puis applique la même fonction que le stockage mémoire (`app/stores/search.py`) ; recharger le contenu garde les compteurs de confirmation | Résultats identiques par construction ; aucune dépendance à l'extension `unaccent`, peut-être absente sur la base managée ; volume faible (une centaine de fiches au plus). | D18 | 3 nov. | **Le conteneur prépare sa base à chaque démarrage** : migrations, puis chargement de `content/` (`scripts/release.py`), sous un verrou PostgreSQL | La base managée n'est peut-être pas joignable depuis nos postes ; la base suit toujours le contenu livré dans l'image ; des instances qui démarrent ensemble passent l'une après l'autre. | D19 | 3 nov. | **Adresse du visiteur lue par l'application** : la valeur ajoutée par le dernier proxy de confiance dans `X-Forwarded-For` (`GOTCHA_PROXY_HOPS`, 1 en production) ; uvicorn ne réécrit plus l'adresse (`--no-proxy-headers`) | La première valeur vient du visiteur, qui peut l'inventer pour contourner les quotas. | D20 | 4 nov. | **Connexion GitHub pour le serveur MCP, sans jeton à copier** : le SDK gère la découverte et PKCE, Gotcha émet ses propres jetons opaques et n'en stocke que l'empreinte ; aucune permission GitHub, jeton GitHub oublié après lecture du profil | Identifier les utilisateurs sans compliquer l'installation ; bloquer un compte coupe l'accès tout de suite. On reprend les routes et les middlewares du SDK au lieu de le monter sur `/`, car un montage sur `/` remplacerait les pages d'erreur du site |
| D21 | 4 nov. | **Positionnement : mémoire opérationnelle du paiement et du déploiement en Afrique**, sans chercher à remplacer Stack Overflow ; au moins 15 pièges bien documentés plutôt que 30 ; les agents peuvent préparer des brouillons, approuvés par leur développeur et vérifiés par un relecteur | Stack Overflow contient presque rien sur nos services, mais l'idée d'une mémoire pour agents existe déjà ailleurs : l'avantage vient du domaine, de la preuve et de la fraîcheur. « Pas de piège inventé » remplace « pas de fiche générée par l'IA » |
| D22 | 4 nov. | **Trois niveaux de confiance affichés** (`sourced`, `reproduced`, `production`), preuve obligatoire au-dessus de `sourced`, date de publication des sources | Distinguer un piège lu d'un piège testé. `last_confirmed_on` n'est plus affiché comme « confirmé » tant que personne n'a confirmé |
| D23 | 4 nov. | **Aperçu public, compte pour le reste** : sans connexion, titre, symptôme, début de la cause, niveau, sources et état des pannes ; solutions, étapes et formulaires réservés aux comptes. Fiche Datacloud entière (`open_access`), code d'accès pour le jury. Une confirmation avec compte demande une preuve, et compte une fois par mois | Identifier les utilisateurs tout en restant trouvable. Le reste n'est pas caché par le gabarit : il n'est pas envoyé. | D24 | 4 nov. | **Les agents contribuent, un humain décide** : `propose_gotcha` demande l'accord du développeur et reste en attente de relecture ; `confirm_gotcha` demande une preuve. | D25 | 4 nov. | **La démo part de Wave, pas de `X-Target-Environment`** | Mesuré sur 80 essais d'un agent : il connaît déjà `X-Target-Environment` sans web ni Gotcha, mais suppose un bac à sable Wave dans tous les essais sans Gotcha. Résultats et limites dans `docs/DEMO.md` |
| D26 | 4 nov. | **Le wolof, première langue locale, sous forme de 3 à 5 explications audio** : enregistrées par un membre, écoutées et relues par un second locuteur, avec transcription et noms techniques conservés. Reportés : interface traduite, reconnaissance et synthèse vocales, autres langues |
